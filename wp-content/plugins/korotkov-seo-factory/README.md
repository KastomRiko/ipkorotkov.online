# Korotkov SEO Factory

Отдельный WordPress-плагин для проекта ipkorotkov.online.

## Текущий статус: 0.7.0 — генерация контента и контроль дублей

Добавлено:
- отдельная административная страница SEO Factory;
- таблицы заданий, ключевых фраз, кластеров, SERP, страниц и журнала;
- таблицы кэша API и учёта вызовов;
- ежедневное событие WordPress Cron;
- внутренний дневной ограничитель Wordstat — 20 запросов суммарно по всем методам;
- минимальный интервал Wordstat — 5 секунд;
- кэширование идентичных запросов Wordstat на 30 дней;
- остановка запросов при HTTP 429 и 503;
- ключ API читается из константы wp-config.php и не выводится в панели;
- синхронный Web Search API: POST /v2/web/search, регион 225 (Россия), XML, до 10 групп на страницу;
- внутренний предел Search API — 100 запросов в сутки, интервал не менее 2 секунд;
- кэш поисковой выдачи — 7 дней;
- страницы выдачи ограничены первыми тремя страницами;
- метод search_and_store($keyword_id, $query_text, $page) разбирает XML через PHP DOM и сохраняет URL, заголовки, сниппеты и позиции в таблицу serp_results;
- повторная запись одного URL для той же фразы в течение суток пропускается.

## Очередь

В панели SEO Factory можно добавить до 30 фраз в партию. Разделители — новая строка, запятая или точка с запятой. Новые задания сохраняются в таблицах keywords/jobs; WP-Cron забирает не более одного задания за запуск. Ошибки и статусы сохраняются, очередь продолжает работу после следующего запуска Cron.

Очередь Search API обрабатывает только органическую выдачу первой страницы. Она не запускает Wordstat, Qwen, генерацию контента или публикацию страниц.

## Защитный флаг биллинга

До подтверждения применимости бонусов к конкретным операциям и проверки актуальных тарифов все сетевые вызовы, которые могут тарифицироваться, заблокированы. Даже при включённой очереди методы вернут ошибку и не отправят запрос, пока явно не задано:

```php
define('KSEF_BILLING_VERIFIED', true);
```

Не добавлять эту константу, пока не подтверждены тарифы и покрытие бонусами. Это дополнительный предохранитель; 4 000 ₽ — общий проектный бюджет, а не автоматически проверяемый баланс Cloud.

## Search API

Используется синхронный REST-метод Yandex Search API:
- POST https://searchapi.api.cloud.yandex.net/v2/web/search
- русский поиск SEARCH_TYPE_RU;
- регион 225 — Россия;
- формат FORMAT_XML;
- поле rawData декодируется из Base64.

Метод реализован в KSEF_Search_Client::search($query_text, $page = 0). Он не вызывается при загрузке/активации плагина. Внутренний лимит — 100 запросов в сутки и минимум 2 секунды между запросами. HTTP 429/503 открывает общий предохранитель API.

Официальная схема REST-запроса и требования к роли/ключу сверены с документацией: https://aistudio.yandex.ru/ru/docs/search-api/operations/web-search-sync

## Подключение ключа

В wp-config.php на сервере (до строки завершения редактирования) задаются константы:

```php
define('KSEF_YANDEX_API_KEY', 'ВАШ_API_КЛЮЧ');
define('KSEF_YANDEX_FOLDER_ID', 'ВАШ_FOLDER_ID');
```

Не добавляйте эти значения в GitHub и не отправляйте их в чат. Если Folder ID уже указан в настройках плагина, константа Folder ID необязательна.

Для Wordstat используются REST-методы:
- `POST /v2/wordstat/top` — GetTop;
- `POST /v2/wordstat/dynamics` — GetDynamics;
- `POST /v2/wordstat/regions` — GetRegionsDistribution;
- `POST /v2/wordstat/regions/tree` — GetRegionsTree.

Клиент не запускает запросы автоматически. Методы принимают подготовленный массив параметров; формы и генерация запросов будут добавлены отдельным этапом после сверки схем каждого метода с документацией.

## Безопасность и бюджет

- Лимит 20 обращений Wordstat в сутки — внутренний предохранитель, не квота Яндекса.
- Интервал Wordstat — не менее 5 секунд.
- Ответы кэшируются; идентичный запрос повторно не отправляется до истечения кэша.
- При HTTP 429 очередь приостанавливается на час, при HTTP 503 — на 15 минут.
- Сбой соединения не оставляет занятую блокировку и не расходует дневной счётчик.
- Для GetTop и GetDynamics в журнал заносится оценка 0,02 ₽ за вызов; для GetRegionsDistribution — 0,05 ₽; GetRegionsTree — 0 ₽. Это расчёт по тарифу 20/20/50 ₽ за 1000 вызовов, а не подтверждение списания с бонусного баланса.
- Общий проектный бюджет — 4 000 ₽; остановка платных операций должна срабатывать до 3 800 ₽ после подключения проверки фактических расходов.
- Очередь Search API подключена и сохраняет SERP первой страницы. Проверка фактического списания и покрытия бонусами не реализована, поэтому сетевые вызовы жёстко заблокированы. Wordstat не включён в очередь. Импорт/экспорт Qwen, полноценная кластеризация и публикация ещё не подключены.

## Ручной обмен с Qwen (0.5.0)

- Экспорт до 30 добавленных ключевых фраз; данные первой страницы органической выдачи включаются, если они уже собраны. Поэтому ручной обмен с Qwen можно проверять и до включения платных запросов.
- CSV содержит фиксированный набор колонок: `keyword_id`, `source_queries`, `serp_competitors`, `recommended_title`, `h1`, `meta_title`, `meta_description`, `short_intro`, `service_scope`, `confidence`.
- CSV сохраняется в UTF-8 с BOM для совместимости с табличными редакторами.
- После обработки в Qwen файл импортируется через административную панель. Проверяются заголовки, ID исходной фразы и обязательные поля; размер файла ограничен 1 МБ, партия — 30 строк.
- Результаты сохраняются в отдельную таблицу `ksef_qwen_imports` со статусом `draft_review`. Последние 10 импортов отображаются в панели.
- Импорт обновляет последнюю запись для соответствующей фразы, не создаёт WordPress-страницы и не публикует контент.
- Используется только ручной обмен через `chat.qwen.ai`; Qwen API, браузерная автоматизация и скрейпинг не применяются.

Экспорт доступен после добавления фраз в очередь. Если SERP ещё не собран, поле конкурентов останется пустым. Внешние API-вызовы по-прежнему заблокированы до отдельной проверки тарифа и бонусов.


## Кластеризация запросов и заготовки страниц (0.6.0)

- Кластеризация выполняется локально по уже сохранённой органической выдаче; новых обращений к Яндексу не делает.
- Для объединения двух фраз требуется минимум два общих URL и Jaccard-пересечение не ниже 0,20.
- Используются URL без схемы, параметров запроса и завершающего слеша; это снижает влияние технических различий адресов.
- Фразы без собранной выдачи не участвуют в кластеризации и не теряются.
- Для каждого кластера создаётся или обновляется запись в `ksef_clusters`; ключевым фразам назначается `cluster_id`.
- Для каждого кластера создаётся запись-заготовка в `ksef_pages`. Если в кластере есть импорт Qwen с обязательными полями, статус заготовки — `draft_review`; иначе — `needs_qwen`.
- Заготовка не является страницей WordPress: `wp_page_id` остаётся нулевым, публикации и изменения сайта не происходят.
- При повторном запуске обновляются существующие кластеры и заготовки, а не создаются новые копии для тех же групп.
- В панели показываются последние 20 кластеров и состояние заготовок.

Порог пересечения — стартовая эвристика, а не гарантия одинакового поискового намерения. Перед публикацией необходима проверка кластеров и содержимого. Автоматическая публикация пока не реализована.


## Полный SEO-контент и проверка качества (0.7.0)

Обмен с Qwen теперь выполняется на уровне кластеров, а не отдельных фраз:
- экспортируется до 30 кластеров за один CSV;
- в задании передаются все фразы кластера, метка кластера и уже сохранённые URL/заголовки/сниппеты конкурентов;
- представитель кластера определяется первой фразой по ID; его keyword_id используется для обратного импорта;
- CSV содержит дополнительные поля article_html, faq_html и internal_links;
- article_html сохраняется через wp_kses_post; FAQ также проходит HTML-фильтрацию;
- полный материал хранится в payload таблицы qwen_imports. Новые столбцы в БД не добавляются, существующие данные не мигрируются и не удаляются.

### Рекомендуемое задание для Qwen

Для каждой строки CSV подготовь самостоятельную SEO-страницу для услуги по России:
1. Сохрани исходный поисковый интент кластера; не добавляй географические обещания и услуги, которых нет в исходных данных.
2. Заполни recommended_title, h1, meta_title, meta_description, short_intro, service_scope и confidence.
3. Напиши содержательную статью на русском языке не менее 700–900 слов в article_html. Используй корректную HTML-разметку: h2, h3, p, ul, ol, li, strong. Не добавляй html/head/body, скрипты, стили, формы и выдуманные цены/гарантии.
4. Включи практические сценарии, состав работ, ограничения, этапы взаимодействия и критерии выбора исполнителя. Не повторяй ключевую фразу механически.
5. FAQ помести в faq_html как 3–5 вопросов с ответами, используя h2/h3 и p.
6. В internal_links укажи только подходящие существующие внутренние URL сайта, если они известны из исходного контекста. Не выдумывай адреса.
7. Верни CSV с исходными заголовками и тем же keyword_id. Не меняй ID, не удаляй строки и не создавай дополнительные строки. Поля serp_competitors и source_queries оставь без изменений.

### Блокирующие проверки импорта

Материал не получает статус ready_for_publish, если:
- отсутствуют обязательные SEO-поля или статья;
- основной текст вместе с FAQ содержит менее 500 слов;
- slug совпадает со slug другой SEO-заготовки;
- H1 или meta title совпадает с другой страницей;
- текст близок к тексту другого кластера: Jaccard-сходство уникальных нормализованных слов не ниже 0,82 (сравниваются последние 500 импортов, материалы того же кластера исключаются).

При ошибках материал и карточка страницы получают статус blocked_review. Успешный импорт получает ready_for_publish. Замечания по длине meta title (ориентир 30–70 символов) и meta description (70–170 символов) выводятся в validation.warnings, но пока не блокируют материал.

Это предварительный автоматический фильтр, а не гарантия экспертного качества или отсутствия семантической каннибализации. Порог 500 слов и Jaccard 0,82 — внутренние стартовые настройки, их следует проверить на реальных материалах. Статус ready_for_publish означает только прохождение этих технических проверок.
