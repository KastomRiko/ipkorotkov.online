# Korotkov SEO Factory

Отдельный WordPress-плагин для проекта ipkorotkov.online.

## Текущий статус: 0.8.1 — атомарная очередь, сверка расходов и восстановление связей страниц

Изменения относительно 0.7.0:

**Wordstat (исправлено по документации Yandex Search API)**
- GetTop: `POST /v2/wordstat/topRequests` (в 0.7.0 был неверный `/top`);
- GetRegionsTree: `POST /v2/wordstat/getRegionsTree`;
- `folderId` передаётся полем тела запроса; заголовок `x-folder-id` убран; Folder ID необязателен для сервисного аккаунта;
- в админке появилась ручная кнопка «Запросить» по каждой фразе (GetTop, Россия, ответ сохраняется в `wordstat_data`); частота используется для выбора головной фразы кластера;
- дневной лимит можно поднять до 1000 (по умолчанию по-прежнему 20);
- `estimated_cost` в `api_usage` — не подтверждённое списание, а консервативный резерв для каждой попытки API; он добавляется к последней ручной сверке `cost`. Для дневного синхронного Search API используется 0,488 ₽ за запрос (488 ₽ / 1000), без учёта возможной ночной скидки;
- допуск платных запросов требует свежего (не старше 24 часов) накопленного `cost` из Yandex Cloud Billing до применения кредитов/бонусов. Значение вручную переносится в настройки; без него или при устаревшей сверке запросы блокируются.

**Очередь Search API**
- задания не сгорают при достижении дневного лимита и бюджета — возвращаются в очередь;
- ошибки 5xx, транспорта, пустая выдача и узел `<error>` в XML повторяются до 3 раз;
- зависшие в `processing` более 10 минут задания возвращаются в очередь;
- ответ без документов или с ошибкой не кэшируется и не считается «исследованной» фразой.

**Кластеризация**
- учитывается только последний снимок выдачи по каждой фразе;
- группы объединяются, только если связана больше половины пар (против цепочечного слипания);
- фактический порог при 10 результатах — 4 общих URL (Jaccard ≥ 0,20);
- имя кластера — самая частотная фраза (если есть Wordstat), иначе самая короткая.

**Создание страниц WordPress** (`class-publisher.php`)
- новые страницы типа «Страница» создаются из материалов со статусом `ready_for_publish`;
- по умолчанию — черновик; режим «сразу опубликовать» включается в настройках;
- автоматический режим выключен по умолчанию, лимит — 3 страницы в сутки (1–50); кнопки «Создать черновик» и «Опубликовать» по одной странице лимит не применяют и в счётчик не входят, а кнопка «для всех готовых» лимит соблюдает;
- параллельные запуски исключаются общей блокировкой MySQL (`GET_LOCK`), поэтому проверка занятого URL и создание страницы выполняются под одной блокировкой;
- если WordPress-страница создана, но запись связи в `ksef_pages` не сохранилась из-за ошибки БД, повторный запуск находит её по `_ksef_page_row_id` и восстанавливает связь без создания дубля;
- повторный импорт материала для кластера, чья страница уже создана, сохраняется в импортах, но созданную страницу и её URL не меняет;
- перед созданием материал проверяется повторно: поля, ≥ 500 слов, запрет script/iframe/form/style;
- занятый URL (slug) или совпадающий заголовок страницы останавливает создание: существующие страницы не изменяются и не получают суффикс «-2»;
- slug строится транслитерацией заголовка (до 80 символов);
- в конец статьи добавляется FAQ и блок «Читайте также» — только из URL, реально ведущих на опубликованные страницы этого сайта;
- черновик публикуется отдельной кнопкой; страница, изменившаяся вручную (не черновик), не затрагивается.

**SEO-теги на сайте** (`class-frontend.php`) для созданных плагином страниц
- `<title>`, `meta description`, Open Graph;
- JSON-LD `FAQPage` из блока FAQ;
- мета-теги подтверждения Яндекс Вебмастера и Google Search Console на главной;
- при активных Yoast SEO, Rank Math, SEOPress или All in One SEO плагин не выводит title/description/OG сам, а записывает значения в их поля.

**Прочее**: автоматическое обновление схемы БД при смене версии, ежедневная очистка кэша и журнала (90 дней), `uninstall.php` (данные удаляются только при `define('KSEF_REMOVE_DATA_ON_UNINSTALL', true);`), ключ API не сохраняется в БД.

## Очередь

В панели SEO Factory можно добавить до 30 фраз в партию. Разделители — новая строка, запятая или точка с запятой. Задания обрабатывает WP-Cron, не более одного за запуск (каждые 5 минут); для надёжности лучше запускать wp-cron.php системным cron. Очередь обрабатывает только органическую выдачу первой страницы.

## Защитный режим биллинга (0.8.1)

Платные вызовы Search API и Wordstat проходят проверки:

1. В `wp-config.php` явно задано `KSEF_BILLING_VERIFIED` со значением `true`. Ветка не добавляет и не включает эту константу автоматически.
2. В настройках вручную указываются накопленные значения за один и тот же период: `cost` из Billing, `credit` (в положительном виде, абсолютная сумма кредитов/скидок), `monetary_grant_credit` и `consumedAmount` из записи гранта. Денежная часть рассчитывается как `expense = cost - credit`. При любом `expense > 0` платные вызовы блокируются.
3. Также указывается точное время окончания гранта в UTC. После этого времени платные вызовы блокируются автоматически. Для данного стартового гранта исходная сумма — 4 000 ₽; доступный остаток оценивается консервативно по большей из величин `consumedAmount` и `monetary_grant_credit`.
4. `consumedAmount` и `monetary_grant_credit` должны совпадать с допуском 0,05 ₽. При расхождении данные считаются несогласованными и платные запросы блокируются. Это fail-closed поведение учитывает возможную задержку обновления отчётов: до их согласования нужно дождаться следующей выгрузки.
5. Сверка действует не более 24 часов. После времени сверки к подтверждённому использованию гранта прибавляется сумма локальных `estimated_cost` всех попыток платных API. Резерв записывается **до** сетевого вызова; если запись в БД не удалась, запрос не отправляется. Неуспешный HTTP-вызов также остаётся в резерве, поскольку провайдер мог его получить.
6. При достижении 3 800 ₽ использования гранта или общей стоимости потребления (из лимита 4 000 ₽ оставляется резерв 200 ₽) новые платные запросы блокируются.

**Ограничение точности:** `estimated_cost` — расчётная сумма по заложенным в плагин ставкам, а не тарифный биллинг. Это консервативный локальный резерв, а не подтверждение списания. Ручная сверка не заменяет автоматический Billing API. Сверяйте все показатели за одинаковый период и по тому же платёжному аккаунту/каталогу.

Поле Billing заполняется вручную. Автоматического подключения к Billing API в 0.8.1 нет. Официальный API Yandex Cloud Billing использует gRPC `ConsumptionCore/GetBillingAccountUsageReport`; минимальная роль — `billing.accounts.viewer`. Значения отчёта предварительные и могут корректироваться в течение семи дней.

## Search API

Используется синхронный REST-метод Yandex Search API:
- POST https://searchapi.api.cloud.yandex.net/v2/web/search
- русский поиск SEARCH_TYPE_RU;
- регион 225 — Россия;
- формат FORMAT_XML;
- поле rawData декодируется из Base64.

Метод реализован в KSEF_Search_Client::search($query_text, $page = 0). Он не вызывается при загрузке/активации плагина. Внутренний лимит — 100 запросов в сутки и минимум 2 секунды между запросами. HTTP 429/503 открывает общий предохранитель API.

Официальная схема REST-запроса и требования к роли/ключу сверены с документацией: https://aistudio.yandex.ru/ru/docs/search-api/operations/web-search-sync

## Подключение ключа

В wp-config.php на сервере (до строки завершения редактирования) задаются константы:

```php
define('KSEF_YANDEX_API_KEY', 'ВАШ_API_КЛЮЧ');
define('KSEF_YANDEX_FOLDER_ID', 'ВАШ_FOLDER_ID');
```

Не добавляйте эти значения в GitHub и не отправляйте их в чат. Если Folder ID уже указан в настройках плагина, константа Folder ID необязательна.

Для Wordstat используются REST-методы:
- `POST /v2/wordstat/topRequests` — GetTop;
- `POST /v2/wordstat/dynamics` — GetDynamics;
- `POST /v2/wordstat/regions` — GetRegionsDistribution;
- `POST /v2/wordstat/getRegionsTree` — GetRegionsTree.

Автоматически Wordstat не запускается: только ручная кнопка в админке.

## Безопасность и бюджет

- Лимит 20 обращений Wordstat в сутки — внутренний предохранитель, не квота Яндекса.
- Интервал Wordstat — не менее 5 секунд.
- Ответы кэшируются; идентичный запрос повторно не отправляется до истечения кэша.
- При HTTP 429 очередь приостанавливается на час, при HTTP 503 — на 15 минут.
- Для GetTop и GetDynamics резервируется 20 ₽ за попытку; для GetRegionsDistribution — 50 ₽; GetRegionsTree — 0 ₽ (не тарифицируется). Резервы соответствуют тарифам, подтверждённым для данного проекта, и учитываются до сетевого вызова. Это расчётный резерв, не подтверждение списания.
- Для Search API до отправки запроса также резервируется оценка в `estimated_cost`. Сумма всех резервов после последней ручной сверки прибавляется к Billing `cost`.
- Общий проектный бюджет — 4 000 ₽; остановка платных операций выполняется при `cost + pending estimated_cost` от 3 800 ₽. При отсутствии/устаревании сверки или ошибке чтения/записи резерва запросы закрываются.
- Очередь Search API подключена и сохраняет SERP первой страницы. Search API и Wordstat резервируют платный вызов под одной атомарной MySQL-блокировкой; дневные счётчики и интервалы проверяются внутри неё. Блокировка удерживается на время сетевого вызова и освобождается в `finally`. При сетевой ошибке резерв не откатывается, так как запрос мог дойти до провайдера и тарифицироваться.
- Wordstat не включён в очередь. Ручной обмен с Qwen, SERP-кластеризация, технические проверки контента и создание WordPress-страниц реализованы. Автосоздание выключено по умолчанию; страницы создаются как черновики.

## Ручной обмен с Qwen (0.5.0)

- Экспорт до 30 добавленных ключевых фраз; данные первой страницы органической выдачи включаются, если они уже собраны. Поэтому ручной обмен с Qwen можно проверять и до включения платных запросов.
- CSV содержит фиксированный набор колонок: `keyword_id`, `source_queries`, `serp_competitors`, `recommended_title`, `h1`, `meta_title`, `meta_description`, `short_intro`, `service_scope`, `confidence`.
- CSV сохраняется в UTF-8 с BOM для совместимости с табличными редакторами.
- После обработки в Qwen файл импортируется через административную панель. Проверяются заголовки, ID исходной фразы и обязательные поля; размер файла ограничен 1 МБ, партия — 30 строк.
- Результаты сохраняются в отдельную таблицу `ksef_qwen_imports` со статусом `draft_review`. Последние 10 импортов отображаются в панели.
- Импорт обновляет последнюю запись для соответствующей фразы, не создаёт WordPress-страницы и не публикует контент.
- Используется только ручной обмен через `chat.qwen.ai`; Qwen API, браузерная автоматизация и скрейпинг не применяются.

Экспорт доступен после добавления фраз в очередь. Если SERP ещё не собран, поле конкурентов останется пустым. Внешние API-вызовы по-прежнему заблокированы до отдельной проверки тарифа и бонусов.


## Кластеризация запросов и заготовки страниц (0.6.0)

- Кластеризация выполняется локально по уже сохранённой органической выдаче; новых обращений к Яндексу не делает.
- Для объединения двух фраз требуется минимум два общих URL и Jaccard-пересечение не ниже 0,20.
- Используются URL без схемы, параметров запроса и завершающего слеша; это снижает влияние технических различий адресов.
- Фразы без собранной выдачи не участвуют в кластеризации и не теряются.
- Для каждого кластера создаётся или обновляется запись в `ksef_clusters`; ключевым фразам назначается `cluster_id`.
- Для каждого кластера создаётся запись-заготовка в `ksef_pages`. Если в кластере есть импорт Qwen с обязательными полями, статус заготовки — `draft_review`; иначе — `needs_qwen`.
- Заготовка не является страницей WordPress: `wp_page_id` остаётся нулевым, публикации и изменения сайта не происходят.
- При повторном запуске обновляются существующие кластеры и заготовки, а не создаются новые копии для тех же групп.
- В панели показываются последние 20 кластеров и состояние заготовок.

Порог пересечения — стартовая эвристика, а не гарантия одинакового поискового намерения. Перед публикацией необходима проверка кластеров и содержимого. Автоматическое создание страниц (с 0.8.0) выключено по умолчанию; черновик публикуется отдельным подтверждением.


## Полный SEO-контент и проверка качества (0.7.0; сохранено в 0.8.1)

Обмен с Qwen теперь выполняется на уровне кластеров, а не отдельных фраз:
- экспортируется до 30 кластеров за один CSV;
- в задании передаются все фразы кластера, метка кластера и уже сохранённые URL/заголовки/сниппеты конкурентов;
- представитель кластера определяется первой фразой по ID; его keyword_id используется для обратного импорта;
- CSV содержит дополнительные поля article_html, faq_html и internal_links;
- article_html сохраняется через wp_kses_post; FAQ также проходит HTML-фильтрацию;
- полный материал хранится в payload таблицы qwen_imports. Новые столбцы в БД не добавляются, существующие данные не мигрируются и не удаляются.

### Рекомендуемое задание для Qwen

Для каждой строки CSV подготовь самостоятельную SEO-страницу для услуги по России:
1. Сохрани исходный поисковый интент кластера; не добавляй географические обещания и услуги, которых нет в исходных данных.
2. Заполни recommended_title, h1, meta_title, meta_description, short_intro, service_scope и confidence.
3. Напиши содержательную статью на русском языке не менее 700–900 слов в article_html. Используй корректную HTML-разметку: h2, h3, p, ul, ol, li, strong. Не добавляй html/head/body, скрипты, стили, формы и выдуманные цены/гарантии.
4. Включи практические сценарии, состав работ, ограничения, этапы взаимодействия и критерии выбора исполнителя. Не повторяй ключевую фразу механически.
5. FAQ помести в faq_html как 3–5 вопросов с ответами, используя h2/h3 и p.
6. В internal_links укажи только подходящие существующие внутренние URL сайта, если они известны из исходного контекста. Не выдумывай адреса.
7. Верни CSV с исходными заголовками и тем же keyword_id. Не меняй ID, не удаляй строки и не создавай дополнительные строки. Поля serp_competitors и source_queries оставь без изменений.

### Блокирующие проверки импорта

Материал не получает статус ready_for_publish, если:
- отсутствуют обязательные SEO-поля или статья;
- основной текст вместе с FAQ содержит менее 500 слов;
- slug совпадает со slug другой SEO-заготовки;
- H1 или meta title совпадает с другой страницей;
- текст близок к тексту другого кластера: Jaccard-сходство уникальных нормализованных слов не ниже 0,82 (сравниваются последние 500 импортов, материалы того же кластера исключаются).
- для кластера должна существовать staging-карточка в `ksef_pages`; иначе импорт сохранится с `blocked_review` и попросит повторить кластеризацию.
- URL-slug ограничивается 180 символами, чтобы не упираться в длину поля `page_slug` (varchar(200)).

При ошибках материал и карточка страницы получают статус blocked_review. Успешный импорт получает ready_for_publish. Замечания по длине meta title (ориентир 30–70 символов) и meta description (70–170 символов) выводятся в validation.warnings, но пока не блокируют материал.

Это предварительный автоматический фильтр, а не гарантия экспертного качества или отсутствия семантической каннибализации. Порог 500 слов и Jaccard 0,82 — внутренние стартовые настройки, их следует проверить на реальных материалах. Статус ready_for_publish означает только прохождение этих технических проверок.
